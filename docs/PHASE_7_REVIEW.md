## Product and sample lesson

Forge is evolving into an AI engineering tutor inside Onshape. Learners perform
CAD operations themselves and should become less dependent on guidance. This
foundation is authored and deterministic: it works without Groq/OpenAI, CAD data
or a model. The single three-step **Sketch to solid** sample covers:

1. Begin with a profile — a sketch defines a 2D outline.
2. Turn the profile into depth — extrusion suits a consistent cross-section.
3. Separate the operation from the result — feature versus solid body.

A learner may think through the example without operating CAD. Optional practice
instructions never infer dimensions or pretend to inspect the learner's work.
Each step separates objective, instruction and engineering Why, offers contextual
vocabulary, and includes conceptual/tool-specific/full-explanation help. The
follow-up question is authored reflection, not a check or inferred ability score.

## Setup and architecture

Setup collects only Beginner / Some experience / Comfortable and one of three
goals: fundamentals, guided project or design reasoning. No default profile is
inferred. Experience adjusts introduction wording; the selected goal frames the
same sample. Guided-project learners are told it prepares them for future projects.
Setup is short, editable before starting, and never a psychological profile.

`learning/lesson.ts` supplies serializable Lesson, LessonStep, VocabularyTerm and
future requirement types, with closed/bounded runtime validation. Stable IDs,
nonblank bounded plain text, unique steps/term IDs and required hint levels are
validated. Optional prerequisites, objectives, completion wording, follow-up,
mistake-investigation and reduced-guidance metadata contain data only. No React
nodes, arbitrary executable rules or external URLs are lesson instructions.

`catalog.ts` loads the local sample synchronously. Empty selection, unavailable
lesson, load failure and invalid content have safe UI/recovery states. No asynchronous
loader or remote catalog is introduced; loader-failure behavior is exercised with
an injected source and representative DEV previews.

`session.ts` owns pure transitions and progress selectors. `LearningProvider`
places ephemeral state above mode tabs and hash subpages; views dispatch actions.
Small Setup, Guidance, Vocabulary and Progress views compose the Learn workspace.
Engineering/business evaluation remains backend-only; this frontend state machine
controls teaching presentation and records local UI interactions only.

## State rules and interaction metrics

- Setup → introduction requires both experience and goal; Begin is explicit.
- Active steps begin with hint level zero and no learner completion.
- Hint requests advance 0 → 1 → 2 → 3. Skipped, repeated, decreasing, out-of-range
  and stale-step requests have no effect. Each reveal replaces the previous level.
- The strongest help is available through deliberate successive requests, without
  delays or requiring a failed attempt. Hint copy is neutral and authored.
- Why and vocabulary disclosures stay in the lesson. Vocabulary counts distinct
  opened term IDs, not toggle clicks. Closing/reopening does not inflate the count.
- Mark step done records learner self-report once. Next step is a separate action;
  stable step IDs reject stale events. All three required steps must be marked
  before View completion summary can finish the lesson.
- Once marked done, a step accepts no new hints. It remains visible until Next.
- Selectors derive completed steps, hints requested, distinct vocabulary opened and
  completed steps without hints. No editable counter or inferred mastery exists.
- The summary states that Forge did not inspect or check CAD. It claims only
  observed lesson interactions and learner-marked steps.
- Reset opens a confirmation; Keep learning/Escape retains progress. Confirming
  reset clears experience, goal, step markers, disclosures and hint/vocabulary history.

No Check my step control is offered. Quiet continuation copy says: “Forge isn’t
checking the model in this sample lesson” and “Model checking becomes available
in supported guided projects.” No synthetic PASS/FAIL/WARNING/UNVERIFIED badge or
verified-result claim is generated by learning.

## Exact session and privacy policy

Learning lives only in React memory in the running panel. Design → Modify → Learn,
settings/history and normal rerenders preserve the profile, active step, disclosures,
hints and counters. Ordinary focus/visibility and unchanged session-status refreshes
preserve it. The existing auth status checks remain; learning adds no polling.

Logout/session expiry unmounts the authenticated workspace. Session CSRF rotation
or any change in connection status resets only learning; it must not remount the account view
and erase its successful disconnect confirmation. Reload, actual iframe destruction,
a new panel or explicit reset starts fresh. The sample has no CAD references and
no dependency on selection/context changes; actual frame navigation still destroys
its memory. The DEV standalone preview has its own local instance and manually
selected fixture state; it is not shared with an authenticated panel.

No localStorage/sessionStorage learning entries, learning database tables, teacher
records, grades, analytics, mastery scores, content logs or new student identity
are added. Existing allowlisted display preferences are unchanged. No credentials
or private CAD enter lesson content or screenshots. No dependencies or lockfiles
changed. No backend model, migration, API, OAuth scope, provider/tool or CAD transport
changed. Learning sends no AI or Onshape requests and never changes CAD. Existing
Design AI and inspector behavior retain their independent authorization boundaries.

and restrained functional glass remain. Reading uses the quiet solid layer;
disclosures and hint actions use existing controls. There are no lesson card grids,
new effects, confetti, idle motion or decorative glass content wrappers.

Native radio groups support arrows/Space with one explicit tab stop per group.

### Repeatable human review procedure

The following procedure is retained as a reference for repeating the accepted flow:

1. In the existing Onshape workspace Part Studio, open the Forge right panel.
2. If needed, use Open Forge in a new tab to complete the existing sign-in flow,
   return and Check panel session. Do not bypass certificate warnings.
3. Choose Learn. Select Beginner, then Learn CAD fundamentals.
4. Select Review sample lesson. Review objectives and Begin lesson.
5. Open Why this step; read how it differs from What to do.
6. Open Sketch (or another vocabulary term) without leaving the step.
7. Request a conceptual hint; only the first level should appear.
8. Select More help: tool-specific hint, then Request full explanation. Each
   replaces the preceding help; Hints requested should reach 3.
9. Scroll to Mark step done. Confirm self-reported wording and the separate Next
   step action. Progress should be 1 of 3 with three hints.
10. Navigate Learn → Design → Learn. The second step and counts must remain.
11. Repeat Mark step done → Next step, then Mark step done → View completion summary.
12. Confirm 3 of 3 steps, three hints, vocabulary actually opened, and two steps
    completed without hints if no more hints were requested. No mastery/CAD result.
13. Reset lesson; first cancel, then confirm. Setup must return with no choices.
14. Narrow the actual panel to 320px; check all controls and vertical scrolling,
    including the continuation area. Also inspect 380/480/640px where practical.
